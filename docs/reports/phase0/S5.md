## Part 1 analysis (Claude Code, 2026-09-24)

Sources, all committed with this report: the pin output above; the raw dumps `docs\reports\phase0\S5\s5_20260907-_OZ80093.NEF.json` and `…\s5_20260110-_Z8A0138-DxO_DeepPRIME XD3.dng.json`; the full profile log and both write-test results, copied from `%TEMP%\LrC-AVG` into `docs\reports\phase0\S5\part1\`; the three screenshots. (The block headed "Content of s5_profiles.log" above repeats the pin output; the log itself is `part1\s5_profiles.log`.)

- **Key dump: done.** 178 distinct keys (NEF 177, DNG 173), process version `15.4`, LR `15.5.1`, pinned to `engine\src\params\sdk-keys.lrc15.json`. The engine loader accepts the file [handle: `readSdkKeysFile("engine/src/params/sdk-keys.lrc15.json")` → "loader OK: 178 keys", run 2026-09-24]. Keys present in only one file: the NEF has 5 `LensProfile*` detail keys that the DNG lacks (`LensProfileDigest`, `…DistortionScale`, `…IsEmbedded`, `…Name`, `…VignettingScale`); the DNG has `Look` (the NEF was dumped on a Camera Matching profile without a Look).
- **Both lens keys exist**, which settles the naming conflict: `EnableLensCorrections` (boolean) and `LensProfileEnable` (number) are both in the live dump. `Texture` exists too, which resolves the LR_SDK_NOTES `[unverified]`. [handle: the `settings` object of `docs\reports\phase0\S5\s5_20260907-_OZ80093.NEF.json` (`"EnableLensCorrections": true`, `"LensProfileEnable": 1`, `"Texture"`); the pinned `engine\src\params\sdk-keys.lrc15.json`; asserted by `engine\tests\params-pinned-lrc15.test.ts`]
- **Nikon (Camera Matching) profile strings, identical for the NEF and the DNG** [handle: `part1\s5_profiles.log`]: `Group: Camera Flat`, `Camera Flexible Color`, `Camera Landscape`, `Camera Neutral`, `Camera Portrait`, `Camera Rich Tone Portrait`, `Group: Camera Standard`, `Camera Vivid`, `Camera Deep Tone Monochrome`, `Camera Flat Monochrome`, `Group: Camera Monochrome`, `Camera Monochrome (Green Filter)`, `(Orange Filter)`, `(Red Filter)`, `(Yellow Filter)`, plus `Camera Standard` as the base for Nikon's creative looks. The `Group: ` prefix is part of the stored string.
- **Adobe profiles are Looks, not CameraProfile values.** While Jim clicked through the Adobe Raw group, every dump reported `CameraProfile = Adobe Standard`. The DNG dump shows why: `Look = { Name: "Adobe Color", UUID: "04FCF287E683E34103866891D7BC669D", Parameters: { CameraProfile: "Adobe Standard", LookTable: …, ToneCurvePV2012: … } }`. Nikon's creative profiles work the same way: the last NEF dump has `Look.Name = "Camera Toy"` over `CameraProfile = "Camera Standard"`. Part 1's log recorded only keys containing "Profile", so **the Adobe profile names were not captured**. Part 2's recorder records the Look.
- **Monochrome profiles report fewer keys** (NEF 159–160, DNG 154–155, vs 177–178 / 172–173 in colour). Some settings disappear from `getDevelopSettings()` in monochrome [handle: the `keys=` column of `docs\reports\phase0\S5\part1\s5_profiles.log`, e.g. NEF 21:11:07 "Camera Deep Tone Monochrome" keys=159 vs 21:10:56 "Camera Vivid" keys=177]. Which settings go is not yet analysed.
- **The write tests did not test anything, and the instructions were at fault.** Step 13 asked Jim to copy a value "up to the next tab" from a log whose tabs are invisible in Notepad. The dialog received the whole tab-joined line, e.g. `Camera Landscape<TAB>LensProfileDigest=…`.
  - Lightroom **silently ignored** the malformed profile string: no error, the read-back was unchanged, 0 keys changed [handle: `part1\s5_writetest_…json`, `S5-writetest.png`]. **The engine must verify every write by reading it back.**
  - `EnableLensCorrections` and `LensProfileEnable` were already on, so writing "on" changed nothing (0 keys changed, `S5-writetestB.png`).
  - `S5-develop-after-write.png` shows **"Profile missing."** under Profile: Adobe Standard after the part-1 write tests. The cause is unverified. Jim has since returned the photo to Adobe Color [stated: Jim, 2026-09-24].
