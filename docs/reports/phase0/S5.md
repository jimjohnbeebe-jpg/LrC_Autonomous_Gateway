## Pre-run findings (Claude Code)

- `SpikeJson.lua` under fengari 0.1.4 (Lua 5.3 VM): Node's `JSON.parse` accepts the output and 17/17 value checks pass (floats, >32-bit integers, escaped strings, UTF-8, nested arrays and objects, empty table → `[]`, NaN/±Inf → strings, sorted keys) [handle: scratch `json_test.cjs`, Phase 0 transcript]. That check caught and fixed one bug: `%d` formatting of integers above 32 bits now uses `%.0f`.
- `pin.ts --dry-run` on the two synthetic dumps: "keys: 9 (array 1, boolean 2, number 3, object 1, string 2)" and the per-dump coverage report [handle: `node spikes\S5\pin.ts engine\tests\fixtures\synthetic-s5-dump-a.json engine\tests\fixtures\synthetic-s5-dump-b.json --dry-run`]. The same conversion is covered by `engine\tests\params-sdk-keys.test.ts` (8 tests pass).
- Naming discrepancy to resolve: Automaat allowlists `LensProfileEnable` (`vendor\automaat\server\src\tool-contracts.ts:81`), while the directive and LR_SDK_NOTES use `EnableLensCorrections`. The write test reads back both; write test B writes `LensProfileEnable`.
- Declared `LrSdkVersion = 13.0`. Whether Lightroom withholds newer keys from lower-declared plugins is [unverified].
