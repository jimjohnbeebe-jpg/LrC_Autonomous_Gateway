# Spike S15: style memory (as-shot cost and nearest edited photos)

## Purpose

Phase 10 row 11 (vault `PHASE10_PLAN.md`, "Third re-plan (2026-10-29, after Phase 11 / #207)", approved by Jim on 2026-10-29 [stated: "Go with recommendations"]): "Spike S15: cost of as-shot measurements of Jim's edited photos (virtual copy, reset, render, measure, remove) and whether nearest neighbours find sensible references."

A later feature could pick a session's reference photos by itself: the edited photos of Jim's whose *as-shot* look is nearest to the photo being edited. Row 8 (PR #276) already takes references by uuid or collection and reports each pass's gap to them. This spike answers two questions before anyone builds the picker:

1. **Cost.** What does one as-shot measurement of an edited photo cost: create a virtual copy, reset it, render it, measure it, remove it? (Medians per step on Jim's machine.)
2. **Usefulness.** Do the nearest neighbours on standardised as-shot features look like sensible style references to Jim? And does the neighbours' edit (final minus as-shot) predict a photo's edit better than the mean edit of all the others?

**Decision rule** (none in PHASES.md for a spike; proposed here [inference]): build the automatic picker only if Jim answers y for most composites (at least 7 of 10) **and** kNN beats the mean on at least 2 of the 4 edit measures. The as-shot cost decides *how*: if the as-shot total is a few seconds a photo, measure on demand; if not, measure once and cache. If either test fails, references stay as now: chosen by the user (row 8).

Jim answers in the PowerShell window running the check, one y/n per composite, instead of in a Lightroom dialog: Claude Code's choice for this spike, **pending Jim's confirmation** (rule 04 "Steps for Jim" allows another way when Jim chooses it; he has not yet chosen it for S15).

## Harness

`npm run s15:check`: `engine\src\devtools\s15-check-cli.ts` (Lightroom side, composites, questions) and `engine\src\devtools\s15-check.ts` (the pure parts: features, z-scores, nearest neighbours, the edit test, step medians, verdict), tested by `engine\tests\s15-check.test.ts`. Devtools only: no product, engine-tool or plugin change. Commands and prerequisites: `.claude\skills\lrc-avg-checks\SKILL.md`.

What it does:
1. Takes the engine's instance lock (Claude Desktop must be quit), connects, and refuses a catalog that `npm run catalog:throwaway` has not marked, unless `-- --i-know` is passed (`engine\src\devtools\throwaway.ts`, as `import:check` does). Then reads the selection: 4 to 20 photos (10 recommended), and each photo's Develop settings.
2. For each photo, in order, each step timed (wall clock in the engine):
   - **final**: the photo rendered by uuid at the session's size and quality (1600 px, quality 75: `DEFAULT_LONG_EDGE`, `PREVIEW_QUALITY`) through the engine's own `PreviewService.render`, and measured (the existing metrics plus row 7's `perceptual`).
   - **create**: one virtual copy named "AVG S15 as-shot", through the engine's `lr_create_virtual_copies` function.
   - **reset**: `lr_reset` on the copy (the existing path; it leaves a "pre-reset" snapshot on the copy, which goes with it).
   - **render**: the copy rendered and measured the same way: the as-shot measurement.
   - **remove**: `lr_remove_photos` on the copy, only after `get_metadata` reads it back as a virtual copy and its uuid differs from the photo's; then the copy is looked up again and must be gone (`unknown_photo`, as `crop:check` does). The get_metadata guard and the look-up are not in the timing.
   A photo whose step fails is recorded, its copy (if any) removed, and the next photo goes on.
3. Reads every photo's settings again and compares them with the start (`settingChanges`, as `crop:check`), and reads the selection back.
4. Gives the bridge back, then with the photos measured both ways (at least 4):
   - **Features** (as shot): L* p2, p5, p20, p50, p80, p95, p98; a* and b* of the shadow, midtone and highlight casts (a tone range with no pixels counts as 0, 0); the 8 HSL band shares; colourfulness; rms contrast. 23 numbers, each turned into z-scores over the photos (a feature with no spread counts 0).
   - **Nearest neighbours**: each photo's 3 nearest other photos, Euclidean on the z-scores, with distances.
   - **Edit test**: each photo's edit is final minus as-shot on L* p50, p5, p95 and colourfulness. For each measure, the mean absolute error over the photos of (a) the mean of the 3 neighbours' edits and (b) the mean of every other photo's edit. kNN is better where (a) is lower.
   - **Composites**: one per photo (sharp, the engine's `composite()`): the photo's final render labelled PHOTO, and its neighbours' finals labelled "REF 1-3 D=<distance>". `composite()` puts them in a row or a column, whichever shows them larger, so four landscape photos come out one above the other [handle: Claude Code's simulator run below, `01_composite.jpg`].
5. Opens the first composite in Windows' default image viewer, then asks once per composite: "Are these sensible style references for this photo?" (y/n).
6. Prints the step medians, the edit test, one line per check, `S15 style memory check: WORKED` or `FAILED`, and `put back: YES` or `NO`. WORKED: every photo measured both ways, the analysis ran, every question answered y or n, every copy removed, every photo's settings and the selection as they started. Jim's n is a result, not a failure. put back YES: every copy removed and every photo's settings as they started.

Results and images: `%TEMP%\LrC-AVG\S15\<run>\`: `s15_check_<run>.json` (each photo's metrics both ways, step times, copy uuid, errors; the medians; features, edits, neighbours, edit test; answers; lines), `NN_final.jpg` and `NN_as_shot.jpg` per photo, and `composites\NN_composite.jpg` (the composites alone in their folder, so the viewer's right arrow should go from one composite to the next [inference: a viewer that steps through the folder in name order]; PR #277 review). Claude Code collects them into `docs\reports\phase10\S15\`.

## Steps for Jim

The check writes only to virtual copies it makes and removes, but it runs on the photos you edited, so it runs on a **copy** of your catalog.

1. In PowerShell:
   ```powershell
   Set-Location D:\Developer\LrC_Autonomous_Gateway
   git fetch
   git switch phase-10/style-memory-spike
   npm install
   ```
2. In Lightroom Classic (your own catalog), Library module (G), select **10 photos you edited yourself**, of different kinds (light and dark, colourful and muted). Ctrl+click adds a photo.
3. File > Export as Catalog... Name it `LrC-AVG S15 copy`, save it in Documents, untick "Export negative files" (the copy then uses your original files where they are) [unverified: option name], click Export Catalog.
4. File > Open Catalog..., choose `Documents\LrC-AVG S15 copy\LrC-AVG S15 copy.lrcat`. Lightroom restarts on the copy.
5. File > Plug-in Manager: LrC-AVG shows Enabled. Close the dialog.
6. Library module, Catalog panel (left): click All Photographs, then Ctrl+A. The 10 photos are selected.
7. Quit Claude Desktop (right-click the Claude icon in the Windows system tray > Quit).
8. In PowerShell:
   ```powershell
   npm run s15:check -- --i-know
   ```
9. Do not click in Lightroom until the questions (about 1 to 3 minutes).
10. The first composite opens in your image viewer: your photo first (PHOTO), then its 3 nearest edited photos (REF 1-3). For each question, look at the composite named in it (the right arrow key in the viewer goes to the next one) and type y or n, then Enter.
11. Wait for "S15 style memory check: WORKED" (or FAILED) and "put back: YES" (or NO), then tell Claude Code "done".
12. In Lightroom, File > Open Recent > your own catalog.

### If something goes wrong

- If it says "select 4 to 20 photos": do step 6 again, then step 8.
- If it says "Another LrC-AVG engine ... is using the Lightroom bridge": do step 7, wait one minute, then step 8 again.
- If it says it cannot connect, or "Lightroom did not connect": do step 5, then step 8 again.
- If Lightroom shows a dialog asking to confirm removing photos: click Remove.
- If it says "put back: NO" and names copies "AVG S15 as-shot": they are in the copy catalog only. Tell Claude Code "done"; the results file lists them.
