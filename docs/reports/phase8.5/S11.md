## Pre-run findings (Claude Code)

Read in the SDK 15.2 API Reference on disk (`D:\Developer\LightRoom Classic Dev Kit\API Reference\`, Readme "15.2 Release", build 202602111402) on 2026-10-12:
- `setRawMetadata` lists `title`, `caption`, `headline` and the other IPTC fields; `gps`, `gpsAltitude` and `pickStatus` ("1 for flag status 'picked', 0 for 'not set', -1 for 'rejected'") arrived in SDK 4.0 [handle: `modules\LrPhoto.html` setRawMetadata].
- `getRawMetadata` reads `isInStackInFolder`, `stackInFolderMembers`, `stackPositionInFolder`, `topOfStackInFolderContainingPhoto`, `countStackInFolderMembers` and `stackInFolderIsCollapsed`. No `LrPhoto` method names a stack [handle: `modules\LrPhoto.html` getRawMetadata and its function list].
- The only stack write is `catalog:addPhoto(path, stackWithPhoto, position)`, which stacks a photo as it is imported ("'above' or 'below'. Default is 'below'") [handle: `modules\LrCatalog.html` addPhoto]. `LrSelection` has `flagAsPick`, `flagAsReject` and `removeFlag`, but no stack call [handle: `modules\LrSelection.html`]. So stacking photos that are already in the catalog has no SDK call [inference: from the reference's function lists; Lightroom's own Photo > Stacking menu is not reachable from a plugin].
- `findPhotos` takes the criterion `"folder"`, "Name of folder -- including all parent folders shown in the Folders panel", with string operations that include `any`, `beginsWith` and `==` (the three the spike tries) [handle: `modules\LrCatalog.html` findPhotos]. `catalog:getFolderByPath` and `folder:getPhotos(includeChildren)` exist [handle: `modules\LrCatalog.html`, `modules\LrFolder.html`].
- `LrPrefs.prefsForPlugin()` keeps "Boolean, number, or string" values and tables of them [handle: `modules\LrPrefs.html`]. The put-back record is kept there.
- `title`, `caption` and `headline` are in `getFormattedMetadata`'s key list, not `getRawMetadata`'s; `pickStatus`, `gpsAltitude` and the stack keys are raw keys [handle: `modules\LrPhoto.html`, the two key lists]. The spike reads each through the call that lists it.
- `withWriteAccessDo`: "changes you make to the database within this call do not have immediate effect, but are written to the database upon successful completion of the callback function" [handle: `modules\LrCatalog.html` withWriteAccessDo]. So the two copies are added in two gates, the second stacked with the first.
- **Contradiction for Jim:** LR_SDK_NOTES (Phase 2) says "No SDK call removes a photo from the catalog" (a community page). SDK 15.2 lists `LrSelection.removeFromCatalog()`, "Removes the selection from the catalog. First supported in version 14.3" [handle: `modules\LrSelection.html`]. The spike does not use it: it acts on the selection, and whether it asks first is [unverified]. Jim removes the two copies by hand.
- The six Lua files compile under Adobe's Lua 5.1 compiler, and every global they use is a Lua or SDK name [handle: `"D:\Developer\LightRoom Classic Dev Kit\Lua Compiler\win\luac.exe" -p` on each file printed nothing. `luac -p -l` listed these globals: `_G` (the one-run-at-a-time flag), `error`, `import`, `io`, `ipairs`, `math`, `pairs`, `require`, `string`, `table`, `tostring`, `type` and `_PLUGIN`. Run 2026-10-12].
